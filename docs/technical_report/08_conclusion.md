## 8.1 训练成果

GomoNova 从零训练 3000 轮，损失稳步下降：

| 指标 | 初始 | 最终 |
|------|------|------|
| 总损失 | 5.97 | **2.09** |
| 策略损失 | 2.99 | 0.79 |
| 价值损失 | 1.00 | 0.73 |

**模型学会了什么？**

- **基本战术**：识别活三、冲四，会进攻也会防守
- **局面判断**：价值头能较准确地评估形势（价值损失降到 0.73）
- **禁手意识**：经过连珠阶段训练，执黑时大多能避开禁手位
- **做棋能力**：会主动构造双重威胁（虽然还不稳定）

棋力达到**业余强手**水平——能稳定战胜大多数 casual 玩家。

## 8.2 设计历程回顾

把整个项目的关键决策串起来：

1. **确立约束**（第 01 章）：不用棋谱、原创架构、从零训练、对战纯推理。这些约束定义了项目的边界和挑战。

2. **搭建地基**（第 02、03 章）：游戏引擎（棋盘、禁手、对称）+ 原创网络（MSAR-Net、16 通道、逐位置门控）。

3. **核心突破**（第 04 章）：引入 MCTS 引导训练。这是棋力远超"纯自模仿"的关键——训练时用搜索生成高质量目标，对战时纯推理。

4. **训练工程**（第 05 章）：三相训练、KL+CE 混合损失、回放缓冲、调参。

5. **性能攻坚**（第 06 章）：从"慢得无法训练"优化到"1 天训完"。扁平树、共享内存并行 MCTS、大模型 DDP，6.9× 加速。

6. **落地应用**（第 07 章）：纯前向推理 + CLI/Web 对弈界面。

> **一条贯穿始终的主线：** "训练用搜索、对战纯推理"。这个 AlphaZero 思想是整个项目的灵魂，理解它就理解了 GomoNova 为什么能 work。

| history_save_interval | 200 | 历史版本保存间隔 |

### 回放 / 评估 / 阶段

| 参数 | 值 | 说明 |
|------|-----|------|
| replay capacity | 2,000,000 | 回放缓冲容量 |
| eval games | 100 | 评估对局数 |
| promote_winrate | 0.55 | 晋升胜率阈值 |
| mcts_start | 300 | MCTS 阶段起点 |
| renju_start | 2400 | 连珠阶段起点 |

> **调参的核心权衡（经验总结）：**
> - `mcts_sims` × `mcts_moves`：越大 MCTS 质量越高但越慢。25×5 是速度-质量平衡点。
> - `train_steps_per_iter`：MCTS 数据质量高，32 步即可，多了浪费时间。
> - `mcts_start`：太早 MCTS 质量差，太晚养成坏习惯。300 轮热身合适。
> - `renju_start`：留 600 轮学禁手足够（禁手比进攻防守简单）。

## 8.4 已知局限

诚实地列出 GomoNova 的不足：

### ① 开局偏弱（已通过强制天元开局修复）

**早期版本的问题：** 第一版模型开局经常下在边角（如 B1、N1），而非天元。原因是纯自博弈缺乏开局引导——网络从随机初始化出发，若"走边"没被强烈惩罚，这个习惯会在自我强化中固化。而且这其实违反了连珠规则（黑第一手必须下天元）。

**修复方案（已实现）：** 在自博弈中**强制天元开局**——每局黑第一手固定下天元（H8），并作为训练样本反复强化"空盘 → 天元"。这是把连珠规则内化进训练分布，对战时纯推理自然下天元，无需推理时加规则。修复后需从头重训（旧权重已固化走边习惯），重训后的模型开局符合规则。

> 这是一个"把规则约束转化为训练分布"的范例：与其在推理时打补丁，不如让模型从数据里学会规则。

**仍存在的开局局限：** 即使第一手正确下天元，后续开局定式（第 2、3 手的最佳应对）仍依赖自博弈探索，可能不如专业开局库精深。这是纯自博弈方法的固有上限。

### ② 战术深度有限

对战时纯推理（无搜索），网络只能输出"直觉"，无法临场计算复杂的多步杀招。面对需要深度计算的战术局面，可能出错。

**原因：** 这是"对战不搜索"约束的固有代价。训练时的 MCTS 知识被蒸馏进网络，但蒸馏不可能 100% 还原搜索能力。

### ③ 自我对弈的策略循环

尽管用了历史对手池缓解，纯自博弈仍可能在某些策略间循环，限制棋力上限。

### ④ 价值头精度

价值损失降到 0.73 后趋于平稳，局面评估仍有误差，影响 MCTS 搜索质量和形势判断。

## 8.5 未来方向

如果要进一步提升棋力，可以考虑：

1. **开局库（不违反约束的版本）**：用 MCTS 在开局做更深搜索（几百次模拟）生成开局数据，而非用人类棋谱。这仍是"从规则中生成"，不违反约束。

2. **对战时轻量搜索**：在保持"主要靠推理"的前提下，对关键局面做极少量搜索（如 10 次模拟）作为补充。但这会突破"纯推理"约束，需权衡。

3. **更大的模型 + 更长训练**：62.7M / 3000 轮受限于算力。更大模型（如 200M）+ 更长训练（10000 轮）通常能显著提升棋力。

4. **更强的 MCTS**：增加模拟次数、改进 PUCT 参数、用更精确的价值网络。

5. **价值头改进**：用更多数据或辅助任务提升局面评估精度。

6. **C++/CUDA 加速**：把 MCTS 树遍历用 C++ 重写，进一步降低自博弈时间，支持更多模拟。

## 8.6 快速上手

```bash
# 安装依赖
pip install torch numpy pyyaml rich click fastapi uvicorn

# 运行测试
python -m pytest tests/ -v

# 冒烟测试训练（2 轮，验证管线）
python scripts/train.py --config configs/train_smoke.yaml

# 完整训练（4× GPU DDP）
torchrun --nproc_per_node=4 scripts/train.py --config configs/train_main.yaml

# CLI 对弈
python -m gomonova.cli.play --checkpoint checkpoints/best.pt --color b

# Web 对弈
python -m gomonova.web.server --checkpoint checkpoints/best.pt --port 8000
# 浏览器打开 http://localhost:8000
```

## 结语

GomoNova 证明了一件事：**仅凭游戏规则，一个神经网络通过自我对弈和搜索引导，就能从零学会下棋，并达到相当的水平。** 它不需要任何人类棋谱，不借用任何现成模型——唯一的输入是规则，唯一的老师是胜负。

这正是强化学习 + 树搜索的魅力所在。希望这份报告不仅讲清了 GomoNova 的实现，更能帮你建立起对"AI 如何从自我对弈中学习"的直觉。理解了这套思想，你就拿到了通往更广阔领域的钥匙。
